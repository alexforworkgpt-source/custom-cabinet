# ADR0005: нижняя навигация разделов и отдельные экраны действий

Status: Implemented locally; exact compiled browser gate PASS

Date: 2026-10-28

## Context

Владелец подтвердил добавление нижнего меню на обычные пользовательские разделы,
сохранение отдельного сценария оформления и проверку через browser TDD.
Прежнее правило только основных URL затрудняло переходы со вторичных страниц.
Один URL покупки содержит и каталог, и оформление; количество подписок не
описывает текущую UI-фазу. ADR0004 о раздельных денежных действиях сохраняется.

## Decision

1. Состав4пунктов и контекстный resolver подписок сохраняются. Обычные вторичные
   страницы имеют явную route eligibility и мобильный родительский пункт.
   Instructions сохраняют существующий Support origin; desktop rules независимы.
2. Каталог показывает меню независимо от списка подписок; checkout/classic wizard,
   отдельные финансовые действия и временные игры/опросы используют собственный
   выход. Оформление не добавляет/не изменяет URL ради видимости панели.
3. Route page владеет `catalogue/section/action`, AppShell — панелью. Небольшой
   React context под Layout передаёт только presentation phase, привязанную к
   history-entry key, с очисткой при уходе. В нём нет API/денежной логики.
4. Используются существующие стили, clearance и keyboard behavior. Не создаются
   второй набор меню, новый CSS, дополнительные пункты или backend изменения.

## Verification and consequences

Публичный seam — фактическая навигация в браузере: прямой вход/reload/back,
подсветка, этап покупки, popup/action, фокус поля и доступность конца статьи.
Будущий sync должен сохранять эти контракты, не копируя upstream visibility rules.
Физическая клавиатура/Telegram не подтверждены headless browser-проверкой.
